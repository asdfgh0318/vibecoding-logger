## Progress

- **morning–afternoon** Audited the local repo + `alphafox02/inmarsat-sniffer`, drafted `merge_plan.html` for a sidecar integration (GPL-3.0 binary as git submodule, JSON UDP feed → FastAPI dashboard).
- **afternoon** Rebuilt the repo from scratch per `plan_2.md`: wiped `tracker/` `web/` `scripts/` `requirements.txt`, archived the old plans under `docs/archive/`, scaffolded `tracker/{controller,targets,sniffer,config.yaml}`, `web/app.py` (two-tab dashboard, scaffolded Inmarsat tab), `scripts/{bootstrap_rpi.sh,motor_test.py}`, `vendor/.gitkeep`. 8 parallel general-purpose subagents wrote the modules in isolation; all dev-machine verifications passed (sim mode). Created GitHub issues #9–#18, one per task. Committed `001074c`.
- **late afternoon** Network bring-up of the Pi was a saga: phone-hotspot AP isolation hid `aruconav.local` despite the Pi being connected; Ethernet cable + IPv6 link-local got us in briefly but kept flapping when the Pi preferred WiFi. Eventually got SSH stable; cloned the repo on the Pi; ran `bootstrap_rpi.sh`; brought the FastAPI dashboard up as a systemd service (`space-station-web.service`) on port 8080.
- **evening** GUI test on real GPIO: `mode: real` confirmed but motors only beep-stalled — and started overheating during diagnosis. Walked through trimpot reset (full CW → minimum), DIP-switch sanity, multimeter coil-pair verification, polarity swaps (B3/B4 then A3/A4), all without rotation. Discovered Waveshare's reference `test.py` works on the same hardware → bug is in our code. Diff'd against their `HR8825.py`: we never drove the MODE pins (16/17/20/21/22/27), and our `STEP_PULSE_HIGH_S` of 5 µs was thin. Patched both, committed `b7ee33e`. Rotation still didn't happen — second pass found ENABLE polarity is inverted on the Waveshare HAT (active-HIGH, not standard active-LOW); patched that too and motors started vibrating instead of just beeping.
- **late evening** Gave up on the bespoke stepping logic — vendored Waveshare's `HR8825.py` verbatim into `tracker/hr8825.py` and rewrote `scripts/motor_test.py` (440 → 71 lines) as a thin click wrapper around it. **Motor 2 rotates correctly** under this wrapper. Motor 1 stopped responding even to Waveshare's own unmodified demo — likely cooked the M1 driver chip during the long beep-stall earlier; hardware swap pending. Committed `de85f51`.
- **late evening (post-handoff)** Refactored `tracker/controller.py` so `StepperAxis` also routes stepping through HR8825. Hit a fun bug: `_LgpioBackend` and HR8825's RPi.GPIO shim each open separate lgpio handles → enable/disable went through the wrong handle and got "GPIO busy". Routed enable/disable via the HR8825 driver. Then hit a quieter bug: the dashboard's limit wizard had previously wedged EL `min/max` to (0, 0) and AZ to (39.04, 39.15) so every goto clamped to the start position and silently no-op'd. Reset both axes to full range. **Motor 2 now jogs from the FastAPI GUI** — full real-hardware loop: browser → /api/jog → controller.AntennaTracker → StepperAxis → HR8825 → motor 2 spins. Committed `1fe386e`.
